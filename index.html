② 三步上手

  1. 解压到你的项目根目录。得到 11 个文件 + secrets/。
  2. 按 TODO 填，顺序别反：先 Memory.md（我是谁/为何做/不做什么）→ 再 Readme.md（怎么协作）→ 最后 State.md（现在在哪）。内核先立，外延后挂。
  3. 真值一律不写进这些文件。密钥存 Vault，体系里只留引用名（写在 Readme 的凭证引用表）。
命令行用户： 
# 复制骨架到新项目
cp -r mrs-ev-template/. ../my-new-project/

# 查看所有待填项
grep -r "TODO" ../my-new-project/

③ 文件都是干什么的

文件回答什么改的频率
Memory.md ●我是谁？为何做？不做什么？最低
Readme.md ●怎么读？怎么写？凭证引用表中
State.md ●现在在哪？卡在哪？下一步？最高
TOOLS.md / repos.md ○有什么工具、仓库？动态
.env.example ○有什么非密配置（只写键名）中
secrets/README.md ○需要哪个凭证（只写"如何取"）按需
.gitignore已预置：忽略 .env 与 secrets/*—
scripts/handoff.py一键生成交接包，交给别的 Agent交接时
Journal.md经验流水，只追加不改写每次任务
scripts/distill.py把流水提炼成内核候选原则攒一批后
● 点 = 内核，自己管 ○ 圆 = 外延，可托管 Vault = 真值，体系外

④ 交给另一个 Agent

交接不是传文件，是传「最小可重建集」。
文件传过去，对方拿到的是数据不是理解 —— 它不知道读哪个、哪些是硬约束、哪个已经过期。 按「能否重建」切一刀，边界不用人划，模型自己就推出来了。
层能否重建交接策略
内核 ●不可重建原样搬运
外延 ○可重建只给索引
真值—永不交接，只给引用名
挂载 同机换 Agent → 一层薄指针 快照 跨人跨机 → HANDOFF.md 单文件 共治 多 Agent 同时 → 内核只读 ＋ 状态分片
两条硬规矩：
① 交接包必须生成，不能手写 —— 手写的必过期；而过期的交接包比没有更危险，它让接手方以为自己懂了。
② 交接必须自带验收 —— 接手方要能回答四问（是什么／卡在哪／下一步／不能碰什么），答不上就回问，不许猜。
一条命令： 
python3 scripts/handoff.py .      # 生成 HANDOFF.md，并做交接前自检
自检会拦下：内核缺文件、遗留 TODO、阻塞为空 —— 这几样任缺其一，交接就是假的。

⑤ 让经验沉淀回内核

不沉淀的教训，会变成反复踩的坑。
一次任务学到的东西，要么留在 State 里等着被覆盖，要么靠人手动搬进 Memory —— 多数是前者。 所以模型留了第三个内核态 J（日志）：任务结束追加一条，攒一批后蒸馏成原则。
M 记忆 · 我是谁 S 状态 · 我在哪 J 日志 · 我摔过哪
M 指导 S　→　S 产生 J　→　J 蒸馏回 M
前两个是呼吸（内核 ↔ 外延 ↔ Vault 的横向流通），第三个是生长。 补上它，太极才自转起来。
J 是「半内核」—— 不可重建，但不参与日常决策，Agent 平时不读它，只在蒸馏时才翻出来。
速判：换一个全新的项目，这条还成立吗？成立才进 M。
一次是意外，两次是模式，三次是原则 —— 频次是天然的去噪器。
人工闸门：脚本只提候选，绝不自动改内核。
Journal → CANDIDATES →（人勾选）→ Memory　——　相可以自动，君不可以。
两条命令： 
python3 scripts/distill.py          # 流水 → 候选提案
python3 scripts/distill.py --apply  # 勾选的 → 落入内核

八原则

1 内核不轻动2 协议先行 3 状态必更新4 外延可插拔 5 虚实分离6 真值入 Vault 7 最小权限8 泄露即轮换
一句话记住它：点不动，圆可扩；点实，圆虚；虚实结合，安全可迁移。
